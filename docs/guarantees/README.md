# Guarantee Ledger

ccreel が外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、
ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる。**
対象は `ccreel` の CLI のサブコマンドと出力、ハブに置くデータの形、push と pull の約束、同梱の skill が頼る `find` の順位である。
fzf の画面の見た目や、rg が無い環境でも仮の順位に使う当たり行数が変わらないことなど、内部の作りは対象外である。地位は `docs/design-decisions.md` と同格である。

- 目的: いま何を約束しているかを1か所で読む。変更の前に、変えてはいけない約束をここから引く。テストの無い約束を Gaps に残す
- 分け方: 約束の対象（CLI と、`internal/` のパッケージ）ごとに1ファイル。テストファイルや Issue の単位では分けない。新しい対象を作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を置き、1行に約束を1つ、宣言文で書く。出典・経緯・設計の理由は書かない（`docs/design-decisions.md` が持つ）。fzf の画面の見た目と、手で確かめる操作は載せない。約束が10行以上のファイルは、内容のまとまりで `##` の見出しを立て、見出しごとに表を置く。1つの見出しには3行以上を入れ、見出しは行の主語になる名詞句にする。10行未満のファイルは見出しを置かない。ファイルは分けない
- 引き方: Issue で「維持する保証」を挙げるときは、Issue の対象のファイルを開く。テストが落ちたら、テストの名前で台帳を検索すると、破れた約束の行が見つかる。約束が守られていることは、全テストを流す CI が確かめる
- 運用: 変更の前にこの README を読み、変更が触れるファイルから「維持する保証」を引く。約束を足す・変える・消すときは、承認を受けた保証節の文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。行を足して10行以上になったら、同じ変更で見出しを立てる。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら移す。乖離は `guarantee-audit` で棚卸しする
