# Search

`ccreel find` と、言葉を渡した `ccreel pick <言葉>` は、セッションに点を付け、1本に決め切れたかを判断する。流れ図は [README](../README.md) の「Claude Code が探す」にある。

## 言葉の読み分け

| 書き方 | 読み方 |
|---|---|
| `@app` | リポの指定。そのリポのセッションだけに絞る。読む本数を40本に絞る前に当てる |
| `#417`・`417` | Issue 番号。ブランチ名か worktree の名前の番号と照らす。本文の語としても探す |
| それ以外 | 題と本文で探す語 |

Issue 番号を本文の語としても探すのは、main の上で「PR #951」と話した会話にはブランチの番号が付かないためである。

## 点

| 当たり方 | 点 |
|---|---|
| Issue 番号がブランチか worktree の名前と一致 | 100 |
| 題に語がある | 語ごとに30 |
| 本文に語がある | 語ごとに、語を含む発言と応答の数の対数で最大20 |
| 全部の語に当たった | 15 |
| 呼んだ場所と同じリポ | 10 |
| 新しさ | 最大5 |

各候補には当たった理由（`issue #417`・`title:締め`・`body:締め×12`・`all terms`・`same repo`）が付く。`body` の数は語を含む発言と応答の数である。Claude Code が利用者に候補を見せて聞くとき、なぜその候補なのかをそのまま示せる。

本文は人の発言と応答の文章だけで数える。ツールの呼び出しと出力、注入された CLAUDE.md は数えない。そこまで数えると、ファイルを読んだだけのセッションや、過去に `ccreel find` でその語を探したセッションが上に来る。

番号はツールの出力の数字にも当たり、候補が数百本になることがある。全部を読むと遅いので、rg で生の jsonl の当たり行数を数えて仮の順位を付け、上位40本だけを読んで点を付ける。仮の順位が同じものは、新しい順に並べる。

## 決め切れたかの判定

1位が2位の1.5倍以上で、かつ20点以上離れているときに `decided: true` を返す。候補が1本だけのときは2位を0点とみなすので、20点に届かなければ決め切らない。

決め切れるかを「数秒で答えが出なければ聞く」のような時間ではなく点差で判断するので、同じ履歴に同じ依頼をすれば、同じ候補と同じ判定が返る。
同梱の skill は、`decided: true` なら1位を `outline` → `show` で読み、`false` なら上位3〜4本を見せて利用者に聞き、候補が無ければ語を変えて1回だけ探し直す。

## 外すセッション

- 呼んでいる Claude Code 自身のセッション（`CLAUDE_CODE_SESSION_ID`）。いま話している会話が「直前のセッション」として返ることはない
- `claude -p` で動かしたセッション（jsonl の `entrypoint` が `sdk-cli`）

発言が1回だけのセッションは、一覧（`list`・`pick`）では外すが、言葉で探す `find` と `search` では探す。
